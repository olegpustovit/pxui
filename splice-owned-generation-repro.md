# Owned command-shell generation regression

Scope is Splice 3257541 and PXUI 222738417d284b99485a7c65e10295ca4c54389d. Prepared-pass shell reuse on the serial Splice paths is blocked at this pin. The staged artifacts are regression hunks for the PXUI checkout. Both passed git apply --check --whitespace=error. Exact preimages, proposals and SHA-256 hashes are adjacent.

## Owning source and deterministic proof

- Splice readback uses begin_commands and complete_through in crates/splice_av/src/lib.rs:297,315. Frames::next does the same in export.rs:98,116. Export::frame does so for each output buffer at export.rs:214,239. When output FPS is higher, the first buffer draws and blits and the further buffers only blit. Each synchronous completion comes before reading the canvas, borrowing a new decoder frame or appending an encoder buffer.
- PXUI ogpu_core/src/backend.rs:1912 commits an owned command, changes its state and takes its driver payload. The prepared pass keeps its RenderInner and Commands clone. At backend.rs:1636, rebegin_commands installs a new DriverCommands in that same Rc after recording-state checks. It clears the active encoder reference. At backend.rs:2283, render_prepared checks the Commands Rc identity and then restarts the retained driver encoder.
- PXUI ogpu_metal/src/backend.rs:522–537 spares a CommandContext only when uniquely owned. A retained Render holds a context clone from render_encoder.rs:168. The old context stays with that Render driver, so backend.rs:652–680 opens the new MetalCommands/context separately. At render_encoder.rs:300–307, restart opens a pass using self.context.cb(), sets self.context.open_encoder and clears its declared residency list. native/pipeline.rs:204 compares against the native command wrapper already held by that encoder. It has no argument for the current core commands' driver context.
- Even when queue.rs:81–92 renews the same native wrapper under both contexts, command_control.rs:145–196 still retains using the old commands_token and list. Texture and buffer retain_for dedup by that token; the current MetalCommands::commit submits a different context's retained list. The problem is the driver generation, with native-wrapper reuse sometimes masking the pixel failure.

The portable mock hunk gives each reusable pass its original driver identity without changing ogpu_core. The test renders, commits and completes epoch 1, reopens the same Commands shell and prepared target, then commits and completes epoch 2. At the pin it observed the active buffer as 0x5 and the pass's owner as 0x4. The temporary control excludes owned passes from the cached restart predicate. The same test then passes. This control is evidence only. It also gives up reuse inside an owned generation.

The Mac hunk uses the actual OGPU Metal conformance harness. It completes a red clear on a 4 × 4 target, reserves that recycled wrapper in an unsubmitted commands object, and overwrites the target with a zero sentinel. Rebegin must now use a different native buffer. The second clear and its completion must reproduce the first GPU readback byte-for-byte. The test drops the prepared target, abandons the reservation, and explicitly tears down texture, queue and device before checking the second image. It reports the Rust allocation count for that forced second generation. The reservation intentionally forces another buffer, so this count describes the repro scope. The staged case requires Mac execution.

## Upstream contract

A retained pass may restart only on its current driver context, including the native buffer, open-encoder state, resource token and pending retention list. A minimal core fix is to tag the cached pass with the owned command payload's generation, advance that generation only after a successful owned rebegin, and recreate the pass if the generation differs. The same generation can continue to restart a pass inside the buffer. Adopted readopt on a genuinely preserved driver context stays eligible. For allocation-free reuse across owned generations, the driver must deliberately rebind its context and native pass to the current buffer and refresh ownership/residency bookkeeping. A stable outer Rc alone does not provide that invariant.

At the Splice call site, keep a shell only after successful commit and GPU completion. Acquisition failure during rebegin leaves the old completed shell intact. Pre-submit failures should abandon a still-recording command and discard the attempted shell. After a commit receipt, a failed completion cannot justify shell reuse or recycling borrowed frame storage. Stop the sequential operation and retire or tear down its GPU context before a retry. A subsequent export step takes a new reader sample, so retrying the same job is not a retry of the failed frame. Cancellation normally runs between completed frames. An owned shell cache must not change the writer's append-after-complete or cancel semantics. Drop prepared targets and any GpuProgram group pass while the queue/device are alive, then release the cached shell, textures and queue, and finish with the device. The live Surface's adopted path uses readopt and has separate lifetime handling.

## Allocations and follow-up measurement

For the pinned successful draw path, code identifies these Rust heap events independently of the outer CommandsInner Rc.

- ogpu_metal/src/backend.rs:680 allocates a Box<MetalCommands> at each driver begin. A cached owned prepared pass prevents returning its context to ctx_spare at prior commit, so the fresh begin typically creates both Rc<CommandContext> and its retained vector. Metal queue pooling may renew the native CommandBuffer wrapper, with a new underlying Objective-C command buffer.
- ogpu_core/src/backend.rs:2251 and ogpu_metal/src/render_encoder.rs:168 allocate the core RenderInner Rc and the Box<Render> when a different shell or generation opens the prepared pass. The lower-level native pass and encoder wrappers have separate spare pools.
- ogpu_metal/src/backend.rs:592 creates the replacement capacity-16 retained Vec on every commit. The previous vector moves into Pending and is dropped at completion. Larger resource sets can grow retention storage as well.
- ogpu_metal/src/queue.rs:114,124–156 pushes a pending entry then takes and consumes its vector during a serial wait. The empty later vector replaces it, so the next serial submit has to grow pending again.
- ogpu_core/src/backend.rs:1135–1143 collects completed GPU timing samples into a fresh Vec. A nonempty duration result allocates. The persistent timing histories are a separate warm-up cost.

mem_sys/counting wraps Rust's global allocator. local_reset and local_alloc_count measure the caller thread's successful allocations, zeroed allocations and reallocations at equal or larger sizes. Deallocation and shrinking reallocations do not add to that count. It includes a counting peer dylib if explicitly registered. It does not measure Objective-C allocations, the native Metal command buffer/blit encoder, AVFoundation reader internals or CVPixelBufferPool writer allocation. Splice calls already provide destination slices for decode/readback. Apple-side AVAssetImageGenerator, the per-IOSurface texture cache and writer pixel buffers still have their own allocation/lifetime behavior.

For a true warmed baseline on Mac, use preallocated RGBA and the warmed read_frame or read_frame_warm call on the same small composition, tally local_alloc_count immediately after the call, then compare bytes to a pre-read frame. Repeat on a warmed Frames::next stream using constant known visual content. For Export::step, a zero duration exercises one source frame per call, including two output submissions at 2× output FPS. Count after the stream is warm and verify the delivered file and cancellation in the existing tests. Keep the Mac timing thresholds and pixel assertions. The forced-generation hunk is a correctness gate, with no warmed Splice performance result claimed.

## Reproduction

The temporary portable workspace uses the current unmodified PXUI core at the pin and the scoped mock hunk, with the ordinary shared target. WSL cargo +1.99.1 check -p ogpu_mock completed in 1.01 s. cargo +1.99.1 t -p ogpu_mock owned_rebegin_prepared_pass_follows_current_driver_generation reproduced the mismatch in 4.423 s wall, with the case taking 0.027 s. The diagnostic control ran the same assertion in 2.491 s wall, with the case taking 0.027 s and passing. The logs are included. portable.py resets the mirror to the pinned core for replay. owned-control.py changes only the temp mirror's restart predicate.

The staged native case is cargo t -p ogpu_metal gpu_owned_rebegin_prepared_target_uses_current_buffer from the PXUI workspace. No Splice production change or Mac command was needed for this handoff.
